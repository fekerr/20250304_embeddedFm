**3. Details and Insights from Sources**

*   **LLMs for Code Optimization:** LLMs can be leveraged to improve algorithmic efficiency and enable automatic code optimization beyond traditional compilers, contingent on a correctness oracle. Evaluation metrics include %Optimized, Speedup, and %Correctness. Decoding strategies like sampling multiple candidates (BEST@k) and selecting the fastest correct one are used. While longer inputs might slightly reduce accuracy, the impact on optimization ability is minimal compared to correctness, suggesting potential integration with program repair methods. Benchmarking on real hardware for performance is challenging due to variability, making simulators like gem5 valuable for reliable and reproducible evaluation.
*   **Interoperable Literate Programming (ILP):** ILP proposes a structured standard for combining code and descriptive content in a narrative style within "documents" (distinct from simple "files" with comments). This structure, particularly when representing API logic as a DAG, is intended to make code more understandable and maintainable for both humans and LLMs. The "zero-step" and "successor-step" methodology provides a clear structure for LLMs. Tools like Mogan facilitate editing and exporting all project files from a single document. Using Scheme for documentation is suggested due to its simplicity and lambda calculus foundation, aligning with the DAG representation. Annotations like `define-with-docs` embed machine-readable metadata (pattern, complexity, examples) to guide LLMs. Experiments on RepoBench show measurable improvements in structural consistency and implementation quality with ILP guidance.
*   **Program Synthesis via Relational Decomposition:** This approach decomposes synthesis tasks into simpler relational subtasks, representing input-output examples as sets of facts rather than entire structures like lists or images. The goal is to learn rules governing the relations between input and output facts. This decomposed representation was shown to outperform standard (undecomposed) representations on various domains like Strings and Lists.
*   **Giano System Simulator:** Giano is designed to meet specific requirements for embedded systems and reconfigurable computing research. Its ability to simulate hardware cores, execute large code bases, and interact in real-time with the external world distinguishes it from other simulators. The architecture includes a bus system for device communication and features like efficient idle condition handling and load profile matching. Debugging is supported, including basic block level analysis for profiling performance bottlenecks. The availability of source code is considered essential for future user modifications.
*   **Split Learning on FPGAs:** This technique involves splitting a neural network's training or inference across a client and a server. The thesis focused on implementing this on FPGAs, likely for resource-constrained or edge devices. The use of hls4ml and Vivado indicates the application of High-Level Synthesis (HLS) to translate higher-level descriptions (e.g., from Keras, as suggested by the mention of `keras-js` in prior discussions and sources) into hardware implementations on FPGAs.
*   **C to x86 Assembly Translation:** Translating from high-level C to low-level x86 assembly presents a significant semantic gap, requiring the model to learn concepts like generating jump instructions for control flow. Data augmentation methods, such as those addressing numerical conversion and switch-case normalization, were shown to drastically improve translation accuracy compared to direct prompting of models like GPT-4-Turbo. The average length of generated x86 assembly code is significantly longer than the input C code. The techniques developed are being analyzed for their generality across other architectures like ARM, MIPS, and RISCV.
*   **ConMover for Move Smart Contracts:** ConMover addresses the challenge of generating code for a low-resource domain like Move smart contracts. Its agentic design, including a Planner Agent using RAG with Sui Move documentation and a Debugging Agent utilizing execution traces, is key. The feedback loop using failed code and traces to generate refined code guides is central to its approach. The framework was found effective even with a limited dataset of Move smart contract categories.
